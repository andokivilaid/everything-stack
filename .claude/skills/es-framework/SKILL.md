# es-framework

## Next.js 16 (reference)

This is **not** the Next.js in most training data. Read `node_modules/next/dist/docs/` before
changing framework-level code. Key rules in this repo:

- `cacheComponents: true`. Any component that reads request data (`cookies()`, `headers()`,
  `usePathname()`, `useSearchParams()`) must sit inside `<Suspense>` — or the build fails with
  "encountered URL data … outside of `<Suspense>`". Clerk's `<SignIn>`/`<SignUp>` and `AppShell` read the
  pathname, so they're wrapped.
- Middleware is `src/proxy.ts`.
- Route handlers that report runtime state call `await connection()` so they aren't prerendered.
- `LayoutProps<"/route">` / `PageProps` are global types generated by `next typegen` (run by `npm run typecheck`).
- Marketing pages are static; authenticated pages are client components backed by Convex hooks.

Adding a page: put public pages under `src/app/(marketing)/`, signed-in pages under
`src/app/dashboard/` (auto-protected by `proxy.ts`), admin under `src/app/admin/`.
Use the official `vercel-react-best-practices` and `vercel-composition-patterns` skills.

## Porting

Keep routes, features and copy identical; keep `npm run verify` + `npm run test:e2e` green
(update their base URLs/ports and the build command).

- **TanStack Start** — `@clerk/tanstack-react-start` (accountless supported: `clerk init --framework tanstack-start`),
  `convex` + `@convex-dev/react-query`. Move route handlers to server functions/API routes.
- **React Router (framework mode)** — `@clerk/react-router` (accountless supported), Convex React client.
- **Vite SPA** — `@clerk/react` + `convex/react`. No server: billing route handlers become Convex
  HTTP actions (`convex/http.ts`) and the server secret is unnecessary. Clerk has **no accountless
  mode** for plain React — the user needs a Clerk account (`clerk init --login`).

Update `framework.provider` in `everything.config.json` and `npm run config:apply`.
